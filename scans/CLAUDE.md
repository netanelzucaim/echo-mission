# scans/

Scanner reports and image metadata. These files are evidence: generated by commands,
never edited by hand. To change one, change the script and rerun it.

## Layout

- `baseline/`: the original `nginx:1.25-bookworm`, produced by `make scan-baseline`
  and `make triage`.
- No probe folders or probe tooling. The what-if measurements for image-filter were
  one-off experiments; their result is the table in `README.md`. The owner wants only
  the fix in the repo.
- `patched/` will be written by `make rescan IMAGE=<image>` in step 6: the same
  layout as `baseline/`, plus `diff.md` and `diff.csv` (comparison with the baseline
  and the VEX check) and `reports/*-vex.*` (the scans with VEX applied).

## Layout of `baseline/`

The owner found a flat folder of 17 files confusing, so it is split by purpose. Keep it
that way, and use the same layout for the patched image's folder.

| Path | Content | Written by |
|---|---|---|
| `README.md` | Plain-language guide to the folder | by hand |
| `stats.md` | Diagrams and tables of the statistics; never hand-edit | `make triage` |
| `triage.md`, `triage.csv`, `triage-details.md` | Both reports merged, ranked, every score explained | `make triage` |
| `review.tsv` | Reviewed reach verdicts per CVE or package, plus nginx.org CVEs the scanners miss | by hand (`triage-cves` skill) |
| `fix-plan.md` | Proposed fix method per CVE, including nginx's own CVEs from upstream's advisories | `make fix-plan` |
| `reports/trivy.json`, `reports/trivy.txt` | Trivy report | `make scan-baseline` |
| `reports/grype.json`, `reports/grype.txt` | Grype report | `make scan-baseline` |
| `reports/versions.txt` | Scan date, image digest, scanner versions | `make scan-baseline` |
| `image/inspect.json` | `docker inspect`: entrypoint, cmd, ports, env, labels, stop signal | `make scan-baseline` |
| `image/history.txt` | `docker history --no-trunc`: the commands that built the original | `make scan-baseline` |
| `image/nginx-V.txt` | `nginx -V`: version and configure flags to reuse in the build | `make scan-baseline` |
| `image/packages.tsv` | Every installed package with version and source package | `make scan-baseline` |
| `image/layout.txt` | Listings of `/`, `/docker-entrypoint.d`, `/etc/nginx`, modules; `id nginx` | `make scan-baseline` |
| `image/linked-packages.txt` | `nginx` plus the packages whose libraries its binary loads; input for the reach score | `make scan-baseline` |
| `image/modules.tsv` | Each optional module package and the packages installed only for it; input for `stats.md` | `make scan-baseline` |
| `image/foreign-packages.tsv` | Packages not built by the distribution; their CVEs must come from upstream advisories, not from the scanners | `make scan-baseline` |
| `image/digest.txt` | Image digest and platform | `make scan-baseline` |
| `image/nginx-security-advisories.html` | Saved copy of nginx's advisories page, input for `fix-plan.md` | `make fix-plan` (first run, or `--refresh`) |

Say "modules", not "components": the owner asked for that word.

## Baseline facts

- Image: nginx 1.25.5, Debian 12.5, linux/amd64,
  `nginx@sha256:a484819eb60211f5299034ac80f6a681b06f89e65866ce91f356ed7c72af059c`.
- Trivy 0.75.0: 775 findings, 494 unique. Grype 0.120.0: 751 findings, 471 unique.
- Merged: 497 unique, 468 reported by both, 15 Critical in both (10 with a fix).
- 94 are in loaded packages (`nginx` plus `libc6`, `libcrypt1`, `libpcre2-8-0`,
  `libssl3`, `zlib1g`); 58 of those have a fix. Top of the danger-and-reach ranking:
  CVE-2023-44487 (see the caution in the root `CLAUDE.md`), then CVE-2024-6119 and
  CVE-2025-15467, both OpenSSL.

## Reading the reports correctly

- Both scanners match on package name and version only. They do not inspect code.
- Absence of a finding is not proof of safety. nginx's own CVEs are missing because the
  nginx.org package is compared with Debian's fixed versions. See the root `CLAUDE.md`.
- Severity often differs between the two for the same CVE, because they pick different
  severity sources. Report both values, not one.
- When comparing two scans, use the same scanner versions and note the database date.
  The Trivy database download has failed before; if a cached database is used, say so.
