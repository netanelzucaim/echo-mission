# scans/: what the scanners found, before and after

Every file here is generated by a `make` command and is evidence, except the two
written by hand: `baseline/review.tsv`. The decision built on them is in
[`docs/triage-decision.md`](../docs/triage-decision.md). To change a
generated file, change its script and rerun it.

```
scans/
├── baseline/            the original nginx:1.25-bookworm
│   ├── stats.md         START HERE: the numbers as diagrams and tables
│   ├── triage.md        the top 40 vulnerabilities, ranked, each explained
│   ├── triage.csv       all 523, ranked, with an explanation column (opens in a spreadsheet)
│   ├── review.tsv       BY HAND: does nginx really run each CVE's code? + nginx/njs CVEs the scanners miss
│   ├── reports/         raw scanner output
│   └── image/           facts about the image
└── patched/             echo-nginx:1.25-bookworm, the image this project builds
    ├── diff.md          START HERE: before/after comparison and the VEX check
    ├── diff.csv         the same, one row per CVE
    ├── triage.csv       both reports merged (input for diff.md)
    ├── reports/         raw scanner output, plus *-vex.* (rescanned with vex/*.json)
    └── image/           facts about the image
```

| I want to... | Open |
|---|---|
| See the overall picture of the original | `baseline/stats.md` |
| See which vulnerabilities matter most | `baseline/triage.md` |
| See which CVEs were chosen to fix, and why | [`docs/triage-decision.md`](../docs/triage-decision.md) |
| Look up one CVE or package | `baseline/triage.csv`, or `reports/trivy.txt` |
| See or change whether nginx really runs a CVE's code | `baseline/review.tsv` |
| See what the patched image fixed | `patched/diff.md` |
| Check a setting of the original image (port, entrypoint...) | `baseline/image/inspect.json` |

## How the files are made

| Command | Writes |
|---|---|
| `make scan-baseline` | `baseline/reports/` and `baseline/image/` |
| `make triage` | `baseline/stats.md`, `triage.md`, `triage.csv` (reads `review.tsv`) |
| `make rescan` | everything in `patched/` |

How to review reach and rank: `.claude/skills/triage-cves/`. How to choose fixes:
`.claude/skills/choose-cve-fix/`. How to rescan and test VEX:
`.claude/skills/rescan-compare-vex/`.

## reports/ and image/

| File | What it is |
|---|---|
| `reports/trivy.json`, `grype.json` | Each scanner's full report, for scripts |
| `reports/trivy.txt`, `grype.txt` | The same as tables, for people |
| `reports/versions.txt` | Scan date, exact image, scanner versions |
| `image/inspect.json` | Settings: entrypoint, command, port, environment, labels, stop signal |
| `image/history.txt` | The commands that built the image, layer by layer |
| `image/nginx-V.txt` | nginx's version and configure flags (reused by the build) |
| `image/packages.tsv` | Every installed package with its version (149 in the original) |
| `image/layout.txt` | Directory listings and the `nginx` user's IDs |
| `image/linked-packages.txt` | `nginx` and the 5 libraries its binary loads (from `ldd`); the "reach" default |
| `image/modules.tsv` | Each optional module package and the packages installed only for it |
| `image/foreign-packages.tsv` | Packages Debian did not build (nginx and its 4 modules); the scanners cannot be trusted for these |
| `image/digest.txt` | The image's digest and platform |

## Baseline facts

- Image: nginx 1.25.5, Debian 12.5, linux/amd64,
  `nginx@sha256:a484819eb60211f5299034ac80f6a681b06f89e65866ce91f356ed7c72af059c`.
- Trivy 0.75.0: 775 findings, 494 unique. Grype 0.120.0: 751 findings, 471 unique.
- Merged: 497 unique, 468 reported by both. `review.tsv` adds 26 CVEs the scanners miss
  (24 from nginx.org, 2 from njs), so `triage.csv` has 523 rows and `stats.md` 497.

## Reading the reports correctly

- Both scanners match on package name and version only. They do not inspect code.
- A missing finding is not proof of safety. nginx's own CVEs are missing because the
  nginx.org package is compared with Debian's version numbers
  ([docs/scanner-blind-spot.md](../docs/scanner-blind-spot.md)).
- The two scanners often rate the same CVE differently. Report both.
- Compare scans made with the same scanner versions, and note the database date.
